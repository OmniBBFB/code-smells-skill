# 外部类库边界

## S23 不完整的类库类 · Incomplete Library Class

- **定义：** 无法直接修改的外部类缺少实际需要的能力，导致调用者反复自行拼装扩展逻辑。这里诊断的是本地集成负担，不将第三方接口不符合个人偏好当成缺陷。
- **候选信号：** 多处对外部对象重复实现相同辅助操作；外部类缺少当前用例必需的查询或转换；本地调用者散落版本相关细节。
- **必要证据：** 查看可用公共 API、外部类不可修改的约定及具体缺失用例；核实已有能力是否已经满足需求，以及当前版本／接口是否在可用材料中确定。使用当前安装代码、锁文件或官方文档；缺失外部资料时不编造 API。不必联网才能审查有完整契约的本地材料。
- **合理例外：** 已有集中包装或辅助函数、只发生一次且清楚的组合操作、库已有适用公共能力、外部模型故意保持最小接口。
- **维护影响：** 重复扩展带来不一致与升级负担，调用者过度了解外部表示；指出具体缺失能力与重复位置。
- **改善方向：** 单项能力可用本地辅助函数，多项相关能力可用包装／本地扩展；保持第三方公共契约和版本兼容，避免 monkey patch 成为全局隐式依赖。
- **上下文不足：** 外部类型／版本／API 不可见或无法确认是否可修改时，只报告集成候选及所需资料，不断言库没有能力。

与 S14、S19 的重合：重复扩展逻辑可作为次要标签；先判断哪个边界导致重复。合并同一根因，避免为一处集成问题重复创建多条发现。
