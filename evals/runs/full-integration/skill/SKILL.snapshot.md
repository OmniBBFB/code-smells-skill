# 代码坏味道审查

支持 23 种代码坏味道，按六类规则审查。审查用户指定范围，以只读报告完成；需要修改时遵循用户实际授权。用户明确指令优先于本 skill 的默认工作方式。

## 定位范围

- 代码片段：检查提供的材料，明确不可见定义与调用者。
- 文件或目录：按指定边界读取；为核实候选按需追踪邻接定义与调用者，报告扩展范围。
- 变更：明确 diff 基线，区分新增问题与既有上下文。缺少基线时先检查可用状态，仅在不能合理确定时询问。
- 全仓库：可分批检查，记录已读范围与未检查部分；不要将抽样结果称为穷尽检查。

读取适用的仓库约定。仓库有 `.codegraph/` 时，在定位或理解代码前优先用可用的 `codegraph_explore` 或 `codegraph explore`；没有索引时跳过，有索引但工具不可用时说明限制并用可用搜索工具。无索引时使用 `rg` 定位候选、定义和调用者。

## 形成并核查候选

先读取 [references/smell-index.md](references/smell-index.md)，按其候选信号对指定范围筛选六类问题；用户只指定某类时聚焦该类。发现候选或用户明确要求该类时，读取对应规则，再作判断：

| 候选／指定类别 | 需要读取 |
|---|---|
| 阶段繁杂、职责膨胀、基本类型承载规则、参数或数据组 | [references/bloaters.md](references/bloaters.md) |
| 重复类型分支、阶段字段、继承契约、等价能力接口差异 | [references/object-orientation.md](references/object-orientation.md) |
| 多种变化原因、同一规则分散、配套继承体系 | [references/change-preventers.md](references/change-preventers.md) |
| 解释实现的注释、重复知识、边界收益低、领域数据缺行为、无效路径、推测扩展 | [references/dispensables.md](references/dispensables.md) |
| 行为归属、内部访问、对象导航、机械转发 | [references/coupling.md](references/coupling.md) |
| 不可修改的外部类缺少实际需要的能力 | [references/library-boundaries.md](references/library-boundaries.md) |

每个候选必须经过对应完整规则的证据与例外检查，不能用索引短句、命名、行数、参数数或点号数量直接判错。无需把无关参考文件全量载入。全范围审查要记录六类的筛选情况；未读取某类别规则时可说“筛选未见候选”，不能称为该类深度审查已完成。

对每个候选：

1. 按规则卡核实定义、调用者、状态不变量和边界职责中与该候选相关的部分。只追踪足以支持或排除判断的上下文。
2. 检查合理解释，如报表投影、DTO、流式 API、有价值的适配或服务边界。读取已有契约比臆测未来需要更可靠。
3. 用当前代码支持具体的维护影响，区分观察与推断。只有实际读取历史才能描述过去修改频率；历史不是每次必查项。
4. 将候选分为“证据充分的发现”“上下文不足”“已排除”。缺失信息可通过现有只读工具获得时先查；不可获得时说明具体缺口，不以追问阻止其他可完成审查。
5. 同一根因合并报告；若完整规则证据也支持相邻类别，明确列主标签与相关标签，不把同一条代码机械复制成多个发现。候选的不确定性同时涉及相邻类别时也可明确列相关标签，而不为覆盖率强行追加标签。

## 输出

先说明检查范围、类别覆盖与主要结果。按实际维护影响排序发现；影响大小与证据确定性分别说明，避免编造精确概率。覆盖记录可分为“已核查候选”“筛选未见候选”“上下文不足”“未检查”，无需列23项空白清单。

每条确定发现包含：

- **问题与类别**：准确描述结构问题，明确主标签和有证据支持的相关标签。
- **位置**：实际文件与行号；用户粘贴代码用片段行号，不虚构文件名。
- **证据**：简短代码引用或定义／调用关系，注明必要的关联位置。
- **影响**：一个有代码依据的修改或一致性风险；假设场景明确标记为推断。
- **建议**：最小改善方向及相关取舍；无需输出完整补丁。

上下文不足项单独列出缺失定义或契约及下一步核实方法，不能混入确定发现。仅在对理解结论有帮助时简述排除理由。没有充分证据时明确说“在本次已检查范围内，未发现证据充分的代码坏味道”，并附实际覆盖限制。

## 完成标准

所选范围与类别中的候选均得到核查或明确的缺失上下文说明；每条确定发现具备可定位证据与维护影响；报告注明未检查范围及各类筛选状态。报告完成即可结束，不要求凑足发现数量或自动重构。新增类别之外的正确性、安全性或性能问题可另行说明，避免强行套用坏味道标签。
